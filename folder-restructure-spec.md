# Folder Restructure Spec: Measure Me

## 1. Goal

The project currently has the React frontend sitting at the repo root. Restructure it into a clean multi-part layout so the project can hold:

- `frontend/`: the existing React + Vite + TypeScript app
- `backend/`: the Node.js + Express API (to be built from the other specs)
- `services/`: other services, such as the Python service for Open3D
- `external/`: third-party or borrowed code and folders we depend on but do not own

**This task is a restructure only.** Do not rewrite app code, do not build the backend, and do not change any app behavior.

## 4. Folder purposes

**`frontend/`** is the React app. It talks only to Supabase Auth (for login) and to the `backend/` API. It never contains server secrets.

**`backend/`** is the Node + Express API. Its internal structure is defined in `docs/specs/backend-architecture-and-user-db-spec.md`. Do not build it in this task.

**`services/`** is for our own services that run separately from the Node API, written in other languages or with other runtimes. Each service gets its own subfolder with its own README, dependency file and `.env.example`. Right now there is one: `cv-service/`, a Python service for Open3D and heavy 3D processing.

**`external/`** is for code we did not write and that we depend on or borrow: cloned repositories, vendored libraries, sample code, model files. Rules:
- Prefer installing dependencies through a package manager (`npm`, `pip`) instead of copying code here.
- If code must live here, prefer a **git submodule** so it stays linked to its upstream repo. Otherwise vendor it into its own subfolder.
- Every subfolder must include a `SOURCE.md` listing: where it came from (URL), the version or commit, the license, and why we use it.
- Never edit files inside `external/` directly. If changes are needed, wrap or fork them.
- Our own app code never lives here.

**`docs/`** is for specs and briefs. Nothing in here is imported by code.

## 6. Config updates after moving

1. **`frontend/vite.config.ts`**: confirm all paths and aliases still resolve. Nothing should point to the repo root.
2. **`frontend/tsconfig*.json`**: confirm `include`, `references` and `paths` entries still point to `src` and the other config files correctly.
3. **`frontend/.oxlintrc.json`**: confirm lint ignore patterns still make sense.
4. **`frontend/package.json`**: confirm scripts (`dev`, `build`, `lint`, `preview`) still work and nothing references `../`.
5. **Code references to `App images`**: search the whole codebase for the folder name and for any import path that goes through it. Update only what broke. Do not rename the folder.
6. **`.gitignore`** (at root): make sure it ignores `node_modules/`, `dist/`, `.env`, `.env.local`, `**/__pycache__/`, `*.pyc`, `.venv/`, and `test_*.txt`. Confirm `.env.example` files are **not** ignored.
7. **`start-dev.bat`**: read it first, then update it so it starts the frontend from `frontend/`. Template:

```bat

start "Frontend" cmd /k "cd /d %~dp0frontend && npm run dev"
rem Uncomment when the backend exists:
rem start "Backend" cmd /k "cd /d %~dp0backend && npm run dev"
```

8. **`README.md`** (root): rewrite the top section to describe the new structure (a short tree and one line per folder) and how to run the frontend. Keep any existing content that is still accurate.

## 7. Cleanup

- `test_err.txt` and `test_out.txt`: open each one. If they are plain command output with nothing useful, delete them (they are covered by the new `.gitignore` rule). If either contains something worth keeping, move it to `docs/` and mention it in the README.

## 8. Rules

- **Before starting:** commit or stash current changes, then create a new branch named `restructure-folders`. Do all work on that branch.
- Do not change application logic, styling, dependencies or versions.
- Do not move or rename `IDE_PROMPT.md`, `App images`, or anything inside `src/`.
- Do not build the backend or the Python service in this task. Placeholders only.
- If a move would break something and you are unsure how to fix it, stop and report the issue instead of guessing.
